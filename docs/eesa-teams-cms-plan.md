# 系學會與系隊後台擴充計畫

> 現況（2026/11/10）：I-1 至 I-6 已實作，11/03 已在本機套用 migration、匯入並核對 14 份內容，以及切換 API。程式／Compose 的導入預設仍為 JSON。I-7 的完整整合驗收與遠端切換待辦。見[實作契約](organization-cms-contract.md)及[切換手冊](organization-cms-rollout.md)。

## 1. 目標與首版範圍

讓管理員與獲授權的部門／系隊編輯者，在同一個後台更新文字、照片、聯絡方式與排序，經預覽、送審及管理員發布後更新公開網站。

首版管理既有 1 份系學會總覽、4 個部門與 9 支系隊。頂層資源的 id 固定，新增或永久刪除部門／隊伍留待後續需求。部門活動、體驗談、系隊活動及聯絡人可以在所屬資源內新增、編輯、排序與移除。

系學會部門活動與系隊活動維持各自的巢狀內容。系隊的 month 包含「整年」「寒假前後」等自由文字，保留這些表示方式。活動區既有日期、分類及發布 API 繼續使用其自身內容契約。

| 資源 | 目前來源 | 後台可維護內容 | 發布與授權單位 |
|---|---|---|---|
| 系學會總覽 | `frontend/src/content/eesa/overview.json` | 橫幅、替代文字、總覽標題與簡介、部門區標題與說明、會長標題與訊息 | 整份總覽，ADMIN 管理 |
| 部門 | `frontend/src/content/eesa/departments/*.json`，4 份 | 中英文名稱、卡片摘要與圖片、橫幅與合照、簡介、部員介紹、額外側欄、活動與詳細圖片、能力、體驗談 | 單一部門，依部門 id 授權 |
| 系隊 | `frontend/src/content/teams/*.json`，9 份 | 隊名、合照、球類圖示、入隊圖片、介紹段落、練習時間區塊、活動、聯絡人與入隊說明 | 單一系隊，依隊伍 id 授權 |

部門／系隊的顯示順序由 ADMIN 調整，名稱與其他內容可由該資源的編輯者維護。順序隨資源版本保存，在發布後影響公開入口與前後項目切換。

系學會頁目前使用 `site.ts` 的共用電子信箱、辦公室與社群連結，這些欄位維持全站共用來源，後續由獨立的全站設定任務管理。系隊 JSON 內的 contact 則納入本次規劃。

## 2. 現況與相容需求

- JSON 模式由 `eesaRepository.ts`、`teamRepository.ts` 載入舊資料。API 模式由組織 Provider 提供已發布快照，後台寫入與匯入共用 `shared/organization-content.ts` 的執行期驗證。
- 部門既有 id 為 activities、technical、publicity、operation。系隊既有 id 為 basketball-men、basketball-women、volleyball-men、volleyball-women、badminton、table-tennis、baseball、tennis、soccer。
- 保留 `/#/eesa`、部門介紹／activities／skills／experiences 子路由、`/#/team`、`/#/team/{id}`、系隊的 `?activity={id}`，以及既有 `/intro/*` 轉址。
- 部門 activities 的 slug、experiences 的 id、系隊 activities 的 id 在各自資源內唯一。保留已存在的識別值，包括數字形式的體驗談 id。發布過的子項可移除以停止公開，改名以修改標題完成，識別值維持固定。
- 移除子項時，同時檢查其側欄引用、搜尋結果、上一篇／下一篇與預設選項。內部引用未調整則阻擋發布。舊子頁停止公開後回內容不存在畫面，系隊失效的 activity 查詢回到第一個公開活動，空活動陣列顯示空狀態。
- 目前宣傳部 photography 與 social-posts 的詳細圖片有專用輪播判斷。首版保留這些既有行為，並以同一批內容驗證後台預覽。
- 系隊圖片目前相對於 `/team/`，系學會使用 `/intro/` 與 `/eesa.jpg` 等網站絕對路徑。匯入器將系隊相對路徑轉為 `/team/...`，保留既有資產網址。公開／私有媒體 API 路徑須直接使用，避免重複補上 `/team/`。
- 保留「待填」、空活動陣列、選填 skills／experiences、null 圖片與既有預留圖片。盤點缺圖時輸出清單，將確認過的舊預留項記為缺圖狀態。新引用的不存在圖片與無權限私有圖片須拒絕保存或發布。

## 3. 內容、權限與介面約定

### 版本與發布

系學會總覽、各部門及各系隊分別保存公開指標、工作指標與版本鎖。部門活動、能力、體驗談與入口卡片屬於同一份部門版本，整份一起送審及發布。系隊介紹、練習、活動與聯絡內容同樣一起發布。

沿用既有活動 CMS 的草稿、送審凍結、撤回、退回、發布、下架及還原語意。寫入攜帶 version，過時回 409。發布與媒體引用、公開指標及操作紀錄在同一交易完成。下架保留歷史，還原建立新草稿。ADMIN 的總覽修改也走草稿與發布流程。

已發布內容繼續對外提供，編輯草稿時保持公開快照穩定。部門卡片的 title、cardDescription、cardImage、order 與詳細內容取自同一個公開版本。

### 授權與媒體

- 新增獨立的部門授權與系隊授權，每筆為使用者與資源的唯一配對。帳號授權介面加入「系學會部門」「系隊」兩組，與既有活動分類／活動授權分開保存。
- EDITOR 可以讀取、編輯、預覽、送審、撤回及還原自己獲授權的資源。ADMIN 管理總覽、順序、授權、發布、退回、下架與紀錄。指定部門授權包含其巢狀活動、能力與體驗談。
- 列表、歷史版本、預覽、私有媒體及還原都逐筆驗權限。撤銷授權或停用後，下一個請求即生效。
- E 的媒體 scope 增加總覽、部門及系隊，維持一張媒體恰好屬於一個範圍的約束。既有活動／分類媒體關聯保留，加入新 scope 時更新檢查約束。
- 目前 MediaReference 直接關聯 ActivityRevision。新增三種內容的引用表，分別以自身版本外鍵與欄位路徑識別引用，保留原有活動引用表。刪除檢查須涵蓋所有引用表，避免其他內容仍使用的圖片被移除。
- 新圖片沿用 JPEG／PNG／WebP、10 MiB、解碼尺寸與重新編碼限制。表單提供圖片替代文字，I-1 固定新圖片 DTO 與舊字串圖片的轉換，匯入時依既有頁面標籤建立替代文字。

### 已接入的 API

下列為已接入的資源路徑。請求格式、版本命令與錯誤見[實作契約](organization-cms-contract.md)。

| 介面 | 用途 |
|---|---|
| `GET /api/v1/public/eesa/content` | 同一讀取快照內的公開總覽與部門內容，總覽下架時為 null，部門僅包含公開項目 |
| `GET /api/v1/public/teams/content` | 同一讀取快照內的公開系隊，依 order、id 排序 |
| `/api/v1/admin/eesa/overview` | 取得總覽的工作／公開指標與版本鎖 |
| `/api/v1/admin/eesa/departments`、`/{id}` | 授權過濾的部門列表及單筆內容 |
| `/api/v1/admin/teams`、`/{id}` | 授權過濾的系隊列表及單筆內容 |
| 上述三類單筆資源的子路徑 | `draft`、`preview`、`revisions`、`submit`、`withdraw`、`reject`、`publish`、`unpublish`、`restore`，沿用活動契約的 HTTP 方法及版本命令 |

內容放在 content，資源 id、version、公開／工作指標及流程狀態留在外層。系隊的練習時間須區分段落、小標題與清單，保留 contact 的 null 與空陣列語意。部門側欄 to 僅接受站內既有路由，發布時確認目標仍可公開存取。

資料庫採總覽、部門、系隊各自的內容及版本模型，重用相同工作流服務與錯誤格式。ADMIN／範圍 Guard、Session、CSRF、操作紀錄沿用平台基礎。所有管理回應禁止快取，公開回應只提供已發布欄位。

## 4. 原訂分工與交付條件

下列角色可以由同一人兼任。多人工作時，I-1 負責共用契約的修改與整合。

| 工作包 | 負責角色與主要工作 | 完成條件 | 相依 |
|---|---|---|---|

| I-2 資料庫與授權 | 後端平台。新增三種資源及版本模型、部門／系隊授權，擴充帳號授權 API、Guard 與紀錄 | migrations 可升級及重跑，活動／帳號／Session 資料保留，跨部門／跨系隊存取被拒絕 | I-1，銜接 C |
| I-3 內容與發布服務 | 後端內容。草稿、版本鎖、審核、歷史還原、下架及唯讀公開快照 | 真實 API 可完成完整流程，公開與工作內容隔離，並行操作不覆寫，引用失效回 409 | I-1、I-2，重用 D，發布整合 I-4 |

| I-7 整合與上線 | 驗收／維運。測試矩陣、備份、隔離環境演練、正式切換及回復手冊 | 真實帳號登入、授權編輯、上傳、送審、發布、公開前台更新全部驗收，備份還原完成 | I-2 至 I-6，納入 H |

### 後台表單分區

- 系學會總覽提供橫幅、總覽文案、部門區文案與會長訊息。
- 部門提供入口卡片與基本介紹、成員介紹、活動與詳細圖片、學習能力、體驗談、額外側欄。選填區塊可啟用或關閉，陣列提供新增、移除、上移及下移。
- 系隊提供名稱與主要圖片、介紹、練習時間、活動、聯絡人與入隊資訊。練習時間以段落／小標題／清單的結構化區塊編輯。
- 列表同時顯示公開與工作版本狀態。送審唯讀、退回原因、歷史版本、預覽及管理員發布沿用 F 的操作。
- 預覽重用系學會總覽、部門及系隊的實際呈現元件。預覽內的活動、能力、體驗談及系隊活動切換保留在後台，以目前表單內容呈現。
- 授權範圍與媒體選圖增加新資源類型，沿用現有元件的錯誤、載入、空狀態及重試處理。

## 5. 原訂進行順序與整合點

1. **固定 I-1**。先盤點 JSON、路由、圖檔與預留值，再完成 DTO、驗證、planned OpenAPI、資料模型設計及共同 fixtures。契約凍結後開出 I-2 至 I-6 的工作分支。
2. **平台線先完成 I-2**。現有 C 的帳號與即時授權是整合前提，D 的工作流與 E 的媒體服務共同承接新 scope。既有 C／D／E 可以和本次規格／mock 工作並行。
3. **四條工作線並行**。平台處理 I-2，內容與媒體處理 I-3／I-4，後台處理 I-5，公開前台與遷移處理 I-6。共用檔案由 I-1 負責人統一合併，其他人透過契約變更清單提出需求。
4. **分開驗收 mock 與真實 API**。I-5、I-6 先以同一批 fixtures 驗收畫面與路由，再逐項接通真實服務。每次整合使用隔離資料庫與測試帳號，紀錄 API 清單及未完成項。
5. **先部門與系隊，再總覽與跨頁**。各挑 1 個內容完整的部門與系隊走完真實端到端流程，之後涵蓋所有 4 部門、9 隊與總覽，最後檢查首頁、導覽、輪播與搜尋。
6. **備份後切換**。先試跑匯入、檢查 14 份頂層內容及所有圖檔、備份資料庫與媒體，再執行正式匯入。同內容重跑跳過，有差異整批拒絕並列出衝突，服務啟動維持獨立於匯入。
7. **完成 I-7**。正式服務發布後，下次讀取即更新內容。暫時凍結對應 JSON 維護，資料庫成為正式來源，舊 JSON 保留為基準。回復優先使用資料庫／媒體備份與已發布版本，保留既有活動 API 與資料。

API 與 JSON 來源設定按新模組分開，規劃為 `VITE_EESA_SOURCE`、`VITE_TEAM_SOURCE`，只接受 api／json。導入期間先明確使用 json，完成相應模組備份、匯入與端到端驗收後再切 api。API 失敗顯示錯誤及重試。模組的入口、詳情、首頁引用、導覽及搜尋統一使用所選來源。

建議按工作包建立 commit，將規格／模型、授權、內容服務、媒體、後台、公開來源與匯入、驗收文件分開。每次交付回報「mock 已驗收」「真實 API 已接通」「正式已切換」各自的狀態。

## 6. 驗收清單

- [ ] 在正式環境比對 1 份總覽、4 部門與 9 系隊的欄位、圖片及順序。11/03 已完成本機資料核對。系隊 month 自由文字與練習時間三種區塊一併檢查。
- [ ] 活企部空內容、舊合照預留、系隊「待填」、null 圖片及空聯絡人可正常顯示與再儲存，沒有自行補成其他內容。
- [ ] ADMIN、部門 EDITOR、系隊 EDITOR 與匿名請求的列表、單筆、歷史、預覽、私有圖檔及直接 API 越權測試通過。授權撤銷後下一個請求失效。
- [ ] 草稿不改變公開頁面、總覽卡片、首頁與搜尋。送審凍結、退回、撤回、版本衝突、並行發布、下架及還原均通過。
- [ ] ADMIN 排序變更只在發布後生效，EDITOR 修改排序被後端拒絕。上下項目及同序值依 id 排列結果一致。
- [ ] 宣傳部多圖輪播、部門活動上一篇／下一篇、體驗談、skills、系隊活動查詢參數與前後隊切換保持正常。
- [ ] 發布或下架後，首頁系學會簡介／部門入口、頁首導覽、首頁系隊快速入口、系隊照片輪播及全站搜尋使用同一公開來源。下架資源從入口與搜尋移除。
- [ ] 所屬子項被移除時，側欄與預設項目的引用有明確處理，歷史版本保留，下架子頁符合內容不存在語意。
- [ ] 圖片上傳、實際格式驗證、私有保護、跨範圍引用、重新編碼、引用刪除保護及重啟後檔案保留通過。
- [ ] 舊 `/intro/*` 轉址、所有保留的公開網址與圖片網址可用。API 與 JSON 模式各自通過，API 失敗可重試。
- [ ] 後台手機與鍵盤操作、未儲存離開提示、欄位錯誤、401／403／409、載入失敗與空狀態通過。
- [ ] 通過既有活動／帳號／媒體回歸、前後端建置、新增權限與版本測試、匯入試跑／重跑、備份還原與正式切換演練。

## 7. 下一步為 I-7 整合驗收與正式切換

先在隔離環境依第 6 節補齊權限、版本、媒體與前台整合驗收，再取得正式網址、連線方式及部署目錄，依[切換手冊](organization-cms-rollout.md)執行備份、匯入比對、API 切換與回復演練。待辦由[總計畫](admin-cms-plan.md#17-未完成任務盤點與後續交辦20261110)的 I-7 追蹤。

## 8. 2026/11/03 接續實作狀態

I-1 至 I-6 已加入共同驗證、資料模型、授權、版本工作流、媒體、後台、公開 Provider 與匯入工具。初次接入後，同日在本機執行 migration、匯入與 API 切換。匯入核對與完整端到端驗收分開記錄，細節見[總計畫第 16 節](admin-cms-plan.md)。

11/10 的部門及系隊列表已與活動共用公開／工作版本標籤，並提供筆數、退回原因及送審版本的檢視入口。角色與瀏覽器操作仍併入 I-7 驗收。
