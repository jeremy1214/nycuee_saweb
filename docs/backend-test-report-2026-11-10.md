# 後端功能測試紀錄（2026/11/10）

本次依使用者要求執行完整後端測試，包含登入、帳號管理、使用者授權及內容編輯。測試使用一次性 PostgreSQL 16 容器與六個專用資料庫；沒有操作既有網站資料庫、帳號或媒體，也沒有部署至現有服務。

最終結果：TypeScript 建置成功，Node 測試報告共 **81 項、81 通過、0 失敗、0 跳過、0 取消**，執行約 29.45 秒。81 項包含 Node runner 的父層整合測試項目。原始輸出保存在本機 `/tmp/nycuee-backend-complete-20261110.log`，暫存檔可能隨系統清理移除。完成後移除一次性測試容器及其匿名資料 volume。

## 執行方式

- Node.js：v20.20.2；資料庫：`postgres:16-alpine`。
- 執行 `npm run db:generate`。
- 建立 `contact_test`、`cms_test`、`content_test`、`account_test`、`security_test`、`workflow_test` 六個隔離資料庫。
- 除由升級測試自行建置的 `cms_test` 外，其餘測試庫先執行全部七個已提交 migrations。
- 設定全部六個測試資料庫環境變數後，在 `backend` 執行 `npm test`，包含 TypeScript 建置與全部 11 個測試檔。HTTP 整合測試會啟動實際 NestJS 應用程式並使用隨機本機連接埠。

測試資料庫對應：

| 環境變數 | 專用資料庫 |
| --- | --- |
| `TEST_DATABASE_URL` | `contact_test` |
| `CMS_TEST_DATABASE_URL` | `cms_test` |
| `CONTENT_TEST_DATABASE_URL` | `content_test` |
| `ACCOUNT_TEST_DATABASE_URL` | `account_test` |
| `SECURITY_TEST_DATABASE_URL` | `security_test` |

這些測試會清除測試資料，升級測試會重設 schema，必須使用一次性隔離資料庫。

## 發現與修正

1. 本機空庫初始化缺少圖片目錄：`bootstrap-content.ts` 原先只傳內容目錄，沒有 Docker 建置產生的圖片清單時無法初始化活動。改為與手動匯入相同，傳入 `LEGACY_PUBLIC_DIR`，預設為 `../frontend/public`；容器無圖片目錄時仍可使用既有清單。新增初始化 CLI 回歸測試。
2. 舊帳號測試將 Token 到期時間設成 1970 年，違反 `expiresAt > createdAt` 資料庫約束，未能到達 API 過期檢查。改為同時設定過去建立與到期時間，保留約束並實際測到過期 Token 拒絕。
3. 新增登入、改密碼、HTTP 授權、分類與活動新增、媒體錯誤及刪除權限、上傳保護、初始化與保留期限測試。
